# Multivariate Survival and Claim Frequency Modelling with Phase-Type Distributions

A bivariate `(claim frequency, claim severity)` risk model for motor
insurance, built on French Motor Third-Party Liability (freMTPL2) data,
with a deployed risk-scoring API.

- **Statistical core:** bivariate normal (MVN) fit on `(log-frequency,
  log-severity)`, conditional-distribution derivation, MANOVA across
  policyholder segments, Mahalanobis/χ² outlier detection.
- **ML layer:** QDA (course-required MVN-based classifier) benchmarked
  against a Gradient Boosting classifier, both flagging policies
  Low / Medium / High risk from rating factors alone.
- **Deployment:** FastAPI service, containerized, Codespaces-ready.

Full write-up of every statistical result: **`reports/ANALYSIS_REPORT.md`**.

## Quickstart

### The fast way — one command

```bash
python run_all.py
```
This trains the models on first run only (skips it if `models/` already
has artifacts), starts the API, waits for it to come up, and opens
`ui/index.html` in your default browser automatically. Press `Ctrl+C`
in that terminal to stop the API. Works the same on Windows, macOS and
Linux (plain Python, no bash/shell script involved) — just make sure
you're in an activated virtual environment with `pip install -r
requirements.txt` already run (see Option B below for that one-time
setup).

### Option A — GitHub Codespaces (recommended for the "deployed app" deliverable)

1. Push this repository to GitHub.
2. Click **Code → Codespaces → Create codespace on main**.
3. The devcontainer automatically installs dependencies and runs the
   full pipeline (`data_prep.py` → `bivariate_analysis.py` →
   `train_model.py`), producing everything under `models/`, `figures/`,
   and `reports/`.
4. Start the API:
   ```bash
   bash run_api.sh
   ```
5. Codespaces will prompt to open a forwarded-port preview for port
   `8000`. Visit `/docs` for the interactive Swagger UI, e.g.
   `https://<your-codespace-url>-8000.app.github.dev/docs`.
6. For the styled dashboard instead of Swagger, open `ui/index.html`
   in a browser and point its "API endpoint" field at your forwarded
   Codespace URL.

### Option B — Local

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python src/data_prep.py           # sanity-check the feature pipeline
python src/bivariate_analysis.py  # MVN / MANOVA / Mahalanobis -> reports/, figures/
python src/train_model.py         # trains & saves QDA + GBM -> models/

bash run_api.sh                   # http://localhost:8000/docs
```

Then, for a polished UI instead of raw Swagger, just double-click
`ui/index.html` (or open it via File → Open in your browser) — it's a
self-contained dashboard that talks to the API running on
`localhost:8000` (no build step, no server needed for the UI itself).

### Option C — Docker

```bash
docker build -t claim-risk-api .
docker run -p 8000:8000 claim-risk-api
```
(The image expects `models/*.joblib` to already exist — either run the
three `src/` scripts locally first and keep them in the build context,
or uncomment the `RUN python src/train_model.py` line in the
`Dockerfile` to train at image-build time.)

## Explainability via Ollama (optional)

`POST /explain` turns a risk score into a plain-language explanation
and underwriting suggestions, using a **local Ollama model** for the
narration. It does not let the LLM invent reasons: the API first
computes real grounding facts (global permutation feature importance
from the trained Gradient Boosting model, this policy's percentile
standing on each important numeric feature, and historical claim
stats for its specific Area/Region/VehBrand/VehGas), and only asks
Ollama to narrate those facts into a summary, a list of key factors,
and recommended actions - returned as structured JSON.

**Setup:**
```bash
ollama serve                 # if not already running
ollama pull llama3.2         # or any model you prefer
```

**Usage:**
```bash
curl -X POST "http://localhost:8000/explain?model=llama3.2" \
  -H "Content-Type: application/json" \
  -d '{
    "VehPower": 9, "VehAge": 12, "DrivAge": 22, "BonusMalus": 160,
    "Density": 8000, "Exposure": 1.0, "Area": "F", "VehBrand": "B12",
    "VehGas": "Regular", "Region": "R24"
  }'
```

The dashboard (`ui/index.html`) has an "Explain with Ollama" button
that appears once a policy is scored - it auto-detects which models
you have pulled via `GET /ollama/models` and lets you pick one.

By default the API talks to Ollama at `http://localhost:11434` and
defaults to the `llama3.2` model. Override either with environment
variables before starting the API:
```bash
export OLLAMA_URL=http://localhost:11434
export OLLAMA_MODEL=llama3.1
uvicorn api.main:app --host 0.0.0.0 --port 8000
```
If Ollama isn't running, `/explain` and `/ollama/models` return a
clear `503` error rather than hanging - `/score` and `/claim-anomaly`
are unaffected either way.

Full field definitions: `GET /schema`, or `models/feature_schema.json`.

## Data source

`data/freMTPL2freq.csv` is a public mirror of the freMTPL2 dataset
(French Motor TPL policies, Charpentier, *Computational Actuarial
Science with R*, CASdatasets), retrieved from a GitHub-hosted course
copy at `OpenActTextDev/ActuarialRegression`. `ClaimTotal` (aggregate
claim amount per policy) is already joined to the frequency table in
this extract, so `Severity = ClaimTotal / ClaimNb` for claimant policies.

|---|---|

| Conditional severity uplift at +2σ frequency | +26.5% |

| MANOVA — Region effect | p = 5.5×10⁻⁶¹ (significant) |
